# 导入方式 A/B 评测：DSH 迁移后的「当前进度」回答保真度（2026-10-21）

## 目的

同一段 Command Code 会话（`be76cf66`，VSCode 插件桥接项目）用 5 种方式导入 DSH 后，
问同一个问题「当前的进度是？」，比较回答与 Command Code 原始回答的接近程度。

## 方法

- 基准答案：Command Code 原始会话对「当前的进度是？」的回答（用户提供）。
- 从每种导入方式的 DSH 会话日志里重建**模型可见上下文**（应用 compaction shadow 规则），
  统一用 `claude -p` 提问、同一提示词，避免被测模型本身差异。
- 可见上下文字符数（text-only）：

| 方式 | 可见字符 | 说明 |
| --- | ---: | --- |
| 全量 full | 208,320 | 全部事件、未压缩 |
| 精简 slim | 58,765 | 工具结果/参数截断、reasoning 丢弃 |
| compact 旧版（6 step） | 49,752 | 抽取式摘要 + 6 个 step |
| compact 自适应 | 13,260 | 抽取式摘要 + 1 个 step |
| compact + LLM 摘要 | 12,094 | Claude 生成的多轮摘要 + 1 个 step |

## 结果：关键事实覆盖

基准答案拆成 12 个关键事实（版本号、无限步数、产物、未验证项、@message 风险、旧版安装、
测试数字、下一步、预算 0/0、模型绑定、产物路径、旧配置残留）：

| 方式 | 覆盖 | 回答长度 | 评价 |
| --- | ---: | ---: | --- |
| 全量 full | 9/12 | 1080 字 | 细节最全（含 npm audit、权限实现进度），但上下文占用最大，且有轻微跑题 |
| 精简 slim | 6/12 | 1061 字 | 明显丢细节：缺产物路径/下一步具体命令，出现无关建议（git init） |
| compact 旧版 6step | **11/12** | 1014 字 | 准确、可执行，但可见窗口仍有 5 万字符 |
| compact 自适应 | **11/12** | 979 字 | 与 6step 同分但更省：1.3 万字符里保住了全部关键动作 |
| compact + LLM 摘要 | **11/12** | 1536 字 | 信息最丰富（产物大小、协议文件、i18n 数字、待拍板设计点），压缩后仍保留语义层次 |

## 结论

1. **slim 不推荐**：虽然能用，但工具/产物级细节丢失明显，回答开始「编」无关内容。
2. **compact（抽取式）已经很好**：11/12，零成本，默认窗口下与基准高度一致。
3. **compact + LLM 摘要最好**：同样窗口下信息密度和结构化程度最高，适合复杂交接；
   代价是一次摘要调用（实测 ~11s / 2090 字）。
4. **全量只在窗口充裕、需要工具级细节时使用**：覆盖 9/12 但上下文大，且更容易被长上下文带偏。

## 建议默认值

- 日常迁移：`--compact`（抽取式，零成本）
- 复杂任务/高保真交接：`--compact --summary-llm claude`（或 codex）
- 需要逐字工具输出：全量（仅当模型窗口足够）
- 不再建议 slim，保留作为极端窗口下的兜底

## 局限

- 单一问题、单一评测模型（claude），事实覆盖用关键词规则统计，非人工逐条打分。
- 回答差异主要来自「可见上下文」；真实 DSH 模型的窗口和风格可能不同。
- 复现：`/tmp/extract-visible.mjs` 重建上下文、`/tmp/ab-answers.mjs` 生成回答（本地脚本，未入库）。
